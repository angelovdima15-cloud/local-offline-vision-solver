# План создания конечного продукта: сначала сквозной MVP

MVP доставляет весь ответ по цепочке: iPhone camera/preview → страницы одной сессии → Windows LAN API → локальный проверяемый Qwen pipeline → пакет PNG/text → iPhone → WatchConnectivity → Watch viewer.

## Реализация в этой итерации

1. Windows: асинхронные LAN jobs, загрузка страниц без уменьшения, идемпотентность повторной отправки, progress/result/package, очередь с одним GPU worker, восстановление после перезапуска, локальное хранение и удаление завершённых сессий.
2. Bonjour: объявление локального сервиса и автоматическое обнаружение телефоном; ручной LAN-адрес как резерв.
3. Один запуск Windows: загрузка модели и API, технические логи, режим проверки транспорта с явно помеченным демонстрационным ответом.
4. iOS: Ultra Wide camera, качественный JPEG, full-screen preview, retake/use, add/remove/reorder pages, solve, progress, сохранение задания/результата и восстановление после закрытия приложения.
5. Watch: один атомарный пакет, проверка целостности/порядка, локальный viewer, haptic/notification, подтверждение доставки и очередь на iPhone.
6. Сборка: готовый Xcode project с iOS и companion watchOS targets; инструкции подписи и установки на реальные устройства.
7. Проверка: API/очередь/пакет/сбои/повторы, существующий solver suite, совместимые fixtures и сценарий приёмки на устройствах без Интернета.

## Границы приёмки

Исходники и проверки транспорта можно подготовить на этой Windows-машине. Здесь отсутствуют macOS/Xcode, целевая RTX 4060 и реальные фотографии: сборка Apple targets, Qwen accuracy/VRAM/latency и WatchConnectivity на паре устройств требуют отдельных запусков. Транспортный demo никогда не считается решением сфотографированного задания.

watchOS управляет показом приложения в foreground. При открытом viewer новый ответ показывается сразу; при закрытом — локальное уведомление с переходом к ответу. Нельзя гарантировать принудительное открытие приложения поверх watchOS.

## После MVP

1. Пройти восемь академических сценариев на RTX 4060, выбрать квантование по эталонной корректности, затем памяти и времени.
2. Улучшить интерпретацию перспективы/мелких символов, проверить полный TeX и сложные выражения.
3. Пройти реальные сетевые сбои, background execution и Watch delivery; измерить полный offline маршрут.
4. Упростить первичную установку и выпуск подписанных приложений; довести retention, читаемость и ограничения нагрузки по результатам использования.
