# Зафиксированные требования продукта

Название: **Local Offline Vision Solver**. Полная исходная спецификация предоставлена пользователем в разговоре. Этот документ сохраняет требования для следующих этапов; не является отчётом об их реализации.

## Приоритеты

1. Правильность ответа.
2. Надёжное чтение фотографий.
3. Строгая изоляция контекста сессий.
4. Работа без Интернета после установки.
5. Доставка iPhone → Windows → iPhone → Apple Watch.
6. Читаемость на Apple Watch.
7. Скорость.
8. Визуальное оформление.

Не сокращать решение и не пропускать проверку ради скорости. Локальное выполнение не гарантирует правильность модели; качество доказывается реальными заданиями и эталонами.

## Оборудование и архитектура

- Windows, RTX 4060 Laptop, 8 ГБ VRAM.
- iPhone 16 Pro Max, предпочтительно Ultra Wide, максимально практическое качество фотографии.
- Apple Watch Series 11, размер корпуса уточняется перед настройкой карточек.
- Qwen3-VL 8B, предпочтительно llama.cpp с CUDA. Квантование выбирается по бенчмарку корректности.
- Нормальная цель 10–30 секунд, приемлемо до 60 секунд; полнота и проверка выше латентности.

Фотография → iOS camera/preview → upload по LAN → Windows image validation/reading/classification/solving/independent verification/recovery → local rendering → iPhone result storage → WatchConnectivity → Watch viewer/haptic.

Никаких cloud services, OpenAI API, внешних OCR API, аккаунтов, логина, удалённого хранения или сетевой телеметрии. После начальной установки Интернет не требуется. Фотографии, ответы и технические логи остаются локально.

## Сессия

Одна сессия = одно независимое академическое задание с одной или несколькими фотографиями, сторонами листа или страницами. Материалы рассматриваются совместно: статья, продолжение, вопросы, варианты ответов. Модель восстанавливает логический порядок страниц. Не решать страницы как независимые задания, если они относятся к одному документу.

Каждый `New Task` полностью очищает старый task/conversation context. Файлы предыдущей сессии можно удалить либо сохранить в локальном debug/archive по настройке. Смена Physics → Computer Science не должна переносить данные предыдущей задачи.

## Языки и предметы

Вход: English, Russian, Kazakh. Выход: основной язык инструкции, кроме явно запрошенного упражнением другого языка. Для смешанного документа определяется основной instructional language.

Первая рабочая версия поддерживает mathematics, physics, computer science, English/IELTS, Kazakh written tasks, geography in Kazakh и multiple choice. Для теста обязательны выбранный вариант и объяснение. Карты/диаграммы/таблицы считаются частью фотографированного условия.

Математика: полная выкладка, промежуточные вычисления, итог. Физика: дано, найти, формулы, подстановка, расчёт, единицы, итог. CS: распознавание типа вопроса, алгоритм/теория/логика/код по требованию. Writing: весь запрошенный текст. Reading: ответы с подходящими краткими обоснованиями. Kazakh/geography: ответ на казахском, без незапрошенного перевода.

## Обработка на Windows

1. Качество каждого изображения: сильное размытие, экспозиция, контраст, перспектива, разрешение, обрезанная страница.
2. Только негенеративная обработка: ориентация, умеренные локальные улучшения, при уверенном обнаружении перспектива. Оригиналы всегда доступны VLM. Нельзя достраивать символы генеративно.
3. Транскрипция/понимание всех страниц: знаки, степени, дроби, схемы, подписи, единицы, вопросы, варианты.
4. Классификация: subject, task_type, language, number_of_questions, requires_math_rendering.
5. Полное решение всей сессии.
6. Независимая проверка оригиналов, чтения, арифметики, логики, единиц, вариантов и всех подпунктов. При практической возможности независимая проверка вычислений. Не давать установку «подтверди ответ».
7. При неоднозначности повторить чтение оригинала с другим кропом/вариантом, сравнить интерпретации, исправить. Retake только когда имеющихся данных действительно недостаточно.
8. Локальный рендеринг и упаковка полного ответа.

Structured result: session_id, detected_language, subject, task_type, problem_text, solution, final_answer, confidence, render_mode, warnings. Keep underlying plain text. Errors/stages/technical metrics доступны телефону через будущий API.

Состояния сервиса: IDLE, RECEIVING, VALIDATING_IMAGES, UNDERSTANDING, SOLVING, VERIFYING, CORRECTING, RENDERING, SENDING, COMPLETE, ERROR. После запуска пользователь не должен работать на ноутбуке для каждой задачи. GPU offload по возможности, CPU/RAM разрешены при недостатке VRAM. Надёжность без OOM важнее полного offload.

Локальные логи: timestamps, inference duration, memory usage, model errors, preprocessing actions, rendering errors. Избегать ненужного дублирования личных данных.

## Карточки

Math/physics используют LaTeX, рендерится на Windows в высококачественные PNG. Watch не разбирает произвольный LaTeX. Длинный текст рендерится локально с качественным шрифтом.

Последовательность `answer_01.png`, `answer_02.png`, …, крупный текст, высокий контраст, минимальные поля, короткие логические части. Ни гигантских вертикальных изображений, ни усечения полного решения.

По возможности первый экран — главный результат, остальные — полное объяснение. Для Writing первый экран начинает сам текст. Полный ответ сохраняется как текст и structured data.

## iPhone

Минимальный workflow сразу при открытии: camera → capture → full-screen preview → Retake / Use Photo. После принятия: список страниц, Add Page / Solve. Первая фотография начинает session; последующие относятся к ней до Solve / New Task.

После результата New Task создаёт полностью новую сессию. Не уменьшать разрешение агрессивно до передачи. JPEG либо совместимый HEIF. Ultra Wide и максимальное практическое качество.

Bonjour/mDNS для обнаружения Windows, Connected status. В исходной спецификации приведён пример `_localvisionsolver._tcp`; реализованный совместимый тип — `_visionsolver._tcp`, поскольку service label ограничен 15 символами. Ручной IP только fallback. Upload: session_id, page_count, page_order, images, полезные device metadata. Без аккаунтов и авторизации.

Progress: Uploading, Reading task, Solving, Checking solution, Rendering, Sending to Watch. Телефон сохраняет structured answer, plain text и cards; автоматически отправляет пакет на часы. Полный результат доступен на телефоне.

При недоступных часах пакет остаётся на iPhone и передаётся позже. Optional saving to Photos разрешено, но не основной транспорт. Ошибки: laptop not found, upload failed, AI backend unavailable, model failed to load, retake required, watch unavailable.

Приёмка: открыть, сфотографировать, preview/retake, добавить страницы, Solve, автоматический upload, получить ответ, автоматически передать Watch без Интернета.

## Watch

Минимальный viewer; не выполняет AI, не обрабатывает фотографии и не общается с ноутбуком напрямую. Транспорт только iPhone ↔ Watch через WatchConnectivity.

Новый пакет хранится целиком, с правильным порядком карточек и session_id. Новая завершённая сессия заменяет активный результат; маленький recent cache допустим. Длинные ответы доступны полностью через swipe/scroll.

Когда приложение может показать результат по правилам watchOS, первая карточка отображается сразу и даётся haptic. Требуемый пользовательский сценарий — фото, ожидание, вибрация, ответ; фактическая возможность автоматического foreground показа подлежит проверке на watchOS в Phase 8.

Короткая ошибка на часах: Processing failed. Check iPhone. Подробности на телефоне. Интернет не нужен, только Apple-supported local connectivity с iPhone.
