# Local Offline Vision Solver

[![Build checks](https://github.com/angelovdima15-cloud/local-offline-vision-solver/actions/workflows/validate.yml/badge.svg)](https://github.com/angelovdima15-cloud/local-offline-vision-solver/actions/workflows/validate.yml)

**Сфотографировать задание → решить локально → получить полный ответ на iPhone и Apple Watch.**

[Первый запуск и передача](DELIVERY.md) · [Скачать сборочные артефакты](https://github.com/angelovdima15-cloud/local-offline-vision-solver/actions/workflows/validate.yml) · [Приёмочные испытания](docs/mvp-acceptance.md)

| Компонент | Технология |
| --- | --- |
| Windows | Python, FastAPI, CUDA llama.cpp, Qwen3-VL 8B |
| iPhone | SwiftUI, Ultra Wide camera, Bonjour, LAN API |
| Apple Watch | SwiftUI, WatchConnectivity, PNG-карточки |
| Данные | Локальные фотографии, отдельные сессии, полный текст и PNG |

IPA в Actions создаётся для физических устройств **без подписи**. Перед установкой требуется переподпись; маршрут установки Watch и реальная точность модели ещё требуют проверки.

**Передача заказчику и сборка при наличии только Windows:** [DELIVERY.md](DELIVERY.md). Репозиторий содержит workflow для проверки Apple-кода на GitHub macOS runner; подписанная установка и аппаратная приёмка ещё необходимы.

**Сквозной MVP в исходниках:** iPhone camera → Windows LAN service → Qwen3-VL 8B → независимое решение → аудит → PNG/text package → iPhone → WatchConnectivity → Apple Watch.

Целевая машина — **RTX 4060 Laptop, 8 ГБ VRAM**. Текущая рабочая машина имеет RTX 3050 4 ГБ; по указанию пользователя реальные модельные прогоны будут выполнены позже на целевом ноутбуке.

Windows pipeline, API/очередь и протокол пакета проверены **45 тестами**; отдельно пройден сквозной transport demo через настоящий HTTP. **В GitHub macOS CI пройдены 5 Swift-тестов, сборки iPhone/Watch для simulator и сборка device IPA с вложенным Watch app. Качество Qwen, VRAM и время 10–60 секунд ещё не измерены на RTX 4060.** Приёмка на трёх устройствах пока впереди. Для установки готовых файлов см. [инструкцию заказчику](docs/customer-start.md).

## Запуск MVP

1. На целевом Windows-ноутбуке выполните установку ниже, затем `scripts\start-backend.ps1`. Этот запуск поднимает модель и LAN API в одном процессе управления.
2. На Mac откройте `apple/LocalVisionSolver.xcodeproj`, задайте подпись и установите `VisionPhone`/`VisionWatch` на настоящую пару устройств. [Сборка Apple](apple/README.md).
3. Разрешите Camera, Local Network и уведомления на Watch. Все устройства подключены к одной локальной сети.
4. iPhone сразу показывает камеру. Снимок → preview → Use Photo → Add Page / Solve → progress → result → автоматическая передача на Watch.

Проверка сети без модели:

```powershell
.\scripts\start-backend.ps1 -Demo
```

Этот режим явно показывает **TRANSPORT DEMO** и не решает сфотографированное задание. С него удобно начинать приёмку камеры/доставки. Протокол и сетевые ошибки: [LAN API](docs/api.md). Реальные шаги приёмки: [MVP checklist](docs/mvp-acceptance.md). [План MVP](docs/mvp-plan.md).

## Первый запуск на целевом ноутбуке

Перенесите исходники проекта, `config.toml`, `scripts`, `examples`, `benchmarks` и `tests`. Не переносите `.venv`: окружение создаётся заново. Нужны Windows x64, Python 3.12+ и совместимый драйвер NVIDIA. CUDA Toolkit для готового бинарного пакета не требуется; CUDA DLL загружает установщик.

Из PowerShell в папке проекта, при наличии Интернета:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1 -DownloadAssets
```

`ExecutionPolicy Bypass` действует только на этот процесс. Скрипт устанавливает Python-зависимости, готовый CUDA 12.4 runtime `llama.cpp b11429`, модель `Q4_K_M` и vision projector `F16` из официального репозитория Qwen. Загрузка — примерно 6.8 ГБ, дополнительное место нужно для архивов, окружения и сессий. Файлы проверяются по SHA256; загрузки модели привязаны к SHA ревизии репозитория, полученной при установке. Сведения сохраняются в `runtime/install-record.json`.

Если установка прервана, повторите её: большие файлы остаются `.part` и загружаются с продолжением, если сервер поддерживает Range. При неверном хеше установщик останавливается и оставляет файл для проверки. Готовые файлы с неизвестным хешем не перезаписываются автоматически.

После установки отключите Интернет. В первом терминале:

```powershell
.\scripts\start-model.ps1
```

Загрузка модели отражается в `runtime/llama/server.log`. Оставьте терминал работающим. В другом терминале:

```powershell
.\.venv\Scripts\python.exe -m local_vision_solver doctor
.\scripts\solve.ps1 "C:\Tasks\page_01.jpg" "C:\Tasks\page_02.jpg"
```

Порядок аргументов — порядок загруженных страниц. Модель дополнительно восстанавливает логический порядок и должна сохранить все страницы. Один вызов `solve` всегда создаёт новую независимую сессию.

Успешный результат сохраняется в `sessions/<uuid>/`:

| Файл | Содержимое |
|---|---|
| `result.json` | Метаданные, полный ответ, аудит, карточки, время и показатели GPU |
| `answer.txt` | Полное решение с исходной LaTeX-нотацией |
| `verified_answer.json` | Проверенный структурированный ответ для повторного рендеринга |
| `cards/answer_01.png`, … | Карточки в порядке чтения |
| `originals/` | Неизменённые входные файлы |
| `processed/` | Ориентированные оригиналы и отдельные негенеративные варианты/кропы |
| `reading.json` | Распознанное задание и классификация |
| `candidate_*.json`, `independent_solution.json`, `audit_*.json` | Локальные материалы проверки |
| `status.json`, `events.jsonl` | Состояние и технические события |

Состояния: `RECEIVING → VALIDATING_IMAGES → UNDERSTANDING → SOLVING → VERIFYING → CORRECTING` при необходимости `→ RENDERING → COMPLETE`. Ошибка записывает `ERROR` с кодом. CLI возвращает ненулевой exit code. В текущей исследовательской версии старые сессии сохраняются локально для оценки; автоматическая очистка архивов будет добавлена вместе с жизненным циклом LAN-сессий.

## Пайплайн и ограничения

Все оригиналы отправляются совместно во все модельные этапы. EXIF-поворот нормализуется без уменьшения разрешения. Проверяются разрешение, контраст, экспозиция и вероятное размытие. Численные пороги — предварительные эвристики; белый фон листа не считается достаточным основанием для отказа. Перспектива, обрезанные условия и продолжение документа проверяются моделью; автоматическое распрямление перспективы пока не реализовано.

При низком контрасте создаётся отдельный умеренный CLAHE-вариант. При неопределённом символе выполняется повторное чтение с кропом оригинала. Генеративное восстановление, внешнее OCR и дорисовка символов отсутствуют. Если после повторного чтения данных недостаточно, возвращается `retake_required`.

Первое решение содержит все требуемые части ответа. Независимый решатель получает исходные изображения и транскрипцию, **не видит первого решения**. Затем отдельный аудит сопоставляет оба решения с оригиналами. Для практических числовых вычислений проверяются предоставленные моделью числовые равенства с помощью ограниченного AST-интерпретатора и точных рациональных вычислений. Это дополнительная проверка арифметики; она не доказывает правильность выбранной формулы, единиц или смысловой интерпретации. Код из учебных ответов автоматически не исполняется.

Проверяется набор идентификаторов вопросов и заявленный язык. Правильность реального языка прозы и смысловая полнота дополнительно зависят от аудита и ручной оценки. `confidence` — субъективная оценка модели, не калиброванная вероятность. Независимые проходы одной модели всё ещё могут повторить одну ошибку.

При ошибке выполняется коррекция и новый аудит. После исчерпания попыток ответ не выдаётся как проверенный. При обрезании вывода лимит увеличивается и выполняется полный повторный запрос; частичный ответ не доставляется. Если не хватает контекста, операция завершается явной ошибкой: страницы не исключаются автоматически.

Сессии используют UUID, свежие сообщения, `cache_prompt=false`, единственный слот, отключённый RAM cache и очистку KV-слота до и после обработки. Файловая блокировка ОС исключает одновременные CLI-сессии в одной рабочей папке. Несколько отдельных рабочих папок не должны одновременно использовать один сервер. Очистка слота — обязательный шаг перед выдачей результата; её ошибка блокирует выдачу.

## Настройка RTX 4060 и выбор квантования

`config.toml` содержит начальные кандидаты, **не готовые результаты оптимизации**:

- `Q4_K_M` + `F16` projector;
- автоматический подбор GPU-слоёв `llama.cpp` с запасом 1024 MiB;
- один слот, контекст 16384, Flash Attention, KV-cache `q8_0`;
- batch 512, microbatch 128.

`--fit` подбирает незаданные параметры в рамках возможностей сборки. GPU projector и рабочие буферы тоже занимают VRAM; этот профиль нельзя считать гарантированно стабильным до реального прогона. При OOM сначала уменьшайте microbatch и переносите projector на CPU, затем корректируйте GPU offload. Снижение точности или разрешения ради времени не выполняется автоматически.

Для другого профиля скопируйте `config.toml` в `config.local.toml` и запускайте:

```powershell
.\scripts\start-model.ps1 -Config config.local.toml
.\.venv\Scripts\python.exe -m local_vision_solver --config config.local.toml solve "C:\Tasks\page.jpg"
```

Загрузка более точного кандидата:

```powershell
.\.venv\Scripts\python.exe scripts\install_assets.py --models-only --quantization Q8_0
```

Укажите новый файл в конфигурации. Q8-веса сами по себе больше 8 ГБ; потребуется часть вычислений на CPU/RAM. Для сравнения Q5_K_M/Q6_K можно загрузить официальный F16 и квантовать локально через `llama-quantize.exe`; не переквантовывайте Q4 как замену исходным весам. Полный F16 требует ещё примерно 16.4 ГБ для скачивания.

Для качества сравнивайте также `F16` и `Q8_0` projectors, удерживая остальные параметры одинаковыми. KV `q8_0` тоже подлежит сравнению с `f16`. Выбор производится сначала по проверенной корректности и качеству чтения, затем по VRAM и времени.

## Бенчмарк на реальных заданиях

Скопируйте `benchmarks/manifest.example.json` в `benchmarks/manifest.local.json`, положите фотографии в `benchmarks/private/` и внесите эталонные ответы/замечания. Нужны все восемь сценариев из спецификации, включая IELTS Writing, географию с картой и многостраничное чтение. Для устойчивой оценки желательно несколько реальных заданий каждого типа, чёткие/сложные снимки, дроби/индексы и последовательность Physics → Computer Science.

С одним уже запущенным кандидатом:

```powershell
.\.venv\Scripts\python.exe -m local_vision_solver benchmark benchmarks\manifest.local.json --label Q4_F16_KV8 --repeats 3 --output benchmarks\private\Q4_F16_KV8.json
```

Остановите модель, смените конфигурацию, запустите следующий кандидат и повторите тот же manifest. Время включает полный пайплайн, включая проверку и рендеринг. Прогрев модели измеряйте отдельно от обычной работы. VRAM измеряется раз в две секунды на уровне всей GPU, включая другие приложения; кратковременный пик может быть пропущен.

Автоматические совпадения `expected_fragments` — только подсказка. Они не подтверждают точность. Заполните `human_correctness_score` и заметки после проверки всех условий, единиц, подзадач, языка и карточек. Заранее согласуйте шкалу, например 0 = неверно/неполно, 1 = полностью правильно. Победитель не выбирается автоматически по скорости или самооценке Qwen.

Phase 1 принимается после получения воспроизводимо качественных результатов на этих реальных фото, а целевой профиль — после устойчивых замеров на RTX 4060. При превышении 60 секунд проверка сохраняется; результат отмечается предупреждением. Максимальный технический таймаут одного запроса сейчас 300 секунд, чтобы длинное решение не обрезалось ради целевого времени.

## Рендерер и проверка без модели

```powershell
.\.venv\Scripts\python.exe -m local_vision_solver render examples\answer_math.json --output examples\math_preview_new
.\.venv\Scripts\python.exe -m local_vision_solver render examples\answer_kazakh.json --output examples\kazakh_preview_new
.\.venv\Scripts\python.exe -m pytest -q --basetemp .cache\tests-new
```

Примеры содержат заранее написанные ответы и не выдаются за результаты Qwen. Повторный `render` требует нового каталога, чтобы сохранить предыдущие карточки.

По умолчанию PNG 832×992 — удвоенные 416×496 пикселей экрана Series 11 46 mm. Для 42 mm используйте 748×892. Проверьте реальные размеры часов и читаемость на устройстве. На карточках крупный белый текст, чёрный фон, небольшие поля, последовательная нумерация. Основной результат идёт первым; письменная работа начинается сразу и полностью разбивается на карточки. Шрифт Segoe UI проверяется на наличие нужных символов, включая казахские буквы.

`math_engine = "mathtext"` поддерживает **математическое подмножество LaTeX**, включая дроби, степени, корни, интегралы, суммы и греческие символы; это не полный TeX. Неподдерживаемая формула и слишком широкое выражение вызывают ошибку, вместо нечитаемого уменьшения или показа сырой разметки. Проверенный текст остаётся в сессии для исправления рендеринга.

Для полного математического TeX выберите `math_engine = "tex"` и заранее установите `latex`, `dvipng`, пакеты `amsmath`/`amssymb`. Отключите автоматическую загрузку пакетов в настройках выбранного TeX-дистрибутива и проверьте режим без Интернета. Этот путь пока не проверен здесь: TeX не установлен. Ввод ограничивается формулами без команд чтения/записи файлов и без shell escape.

## Работа без Интернета и локальные данные

После установки solver обращается только к буквальному loopback-адресу `127.0.0.1`/`::1`, использует встроенные data URL для изображений, отключает proxy environment и HTTP redirects. `llama.cpp` запускается с локальными путями и `--offline`. Публичный OpenAI API и OpenAI SDK не используются; путь `/v1/chat/completions` — локальный протокол сервера `llama.cpp`.

Логи событий не содержат base64 изображений или копии текстов задания; транскрипция/решения сохраняются в исследовательских файлах сессии. Не включайте подробный debug-лог сервера, если он дублирует содержимое задач. Аккаунтов, телеметрии, внешнего OCR, cloud storage и синхронизации нет. Онлайн-установщик находится отдельно и никогда не импортируется runtime-пайплайном.
